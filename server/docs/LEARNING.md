# Learning, memory and speech in the Stratoks simulation

No external or paid AI/LLM API is used anywhere. Everything below runs locally inside `server/src/brain.js` and `actions.js`. This is a small reinforcement-learning mechanism, **not** a claim of consciousness or understanding.

## Decision loop
When a creature has no current action it **observes**, builds a feature vector `f` (12 numbers in 0..1), lists the **feasible actions**, scores each with a learned linear utility `U(a) = b_a + w_a · f`, and samples one with a softmax (temperature 0.35). The chosen action runs until it finishes or is interrupted, then a reward is computed and the weights of that action are updated.

**Observations (`FEATURES`)**: hunger, tiredness, hurt (1−health), proximity to the nearest known food, food known, homeless, carrying material, an open construction site/repair exists, nearby company, fire danger, storm, loneliness. Food is only known if the creature perceived it (radius 12) and remembered it (10 remembered spots with last seen amount).

**Actions**: EAT, REST, GATHER_WOOD, GATHER_STONE, BUILD, SOCIALIZE, MATE, WANDER, FLEE, APPROACH (a visitor wallet), AVOID (a visitor wallet). Feasibility encodes hard rules (juveniles cannot build/mate, MATE needs bonded partner, shelter, health, food…).

**Reward** (at action end, clipped to [-2, 2]): `Δhunger/25 + Δenergy/40 + Δhealth/20 + task bonus − 0.002·duration`, task bonuses: material gathered/deposited, build work and stage completion, social contact, bonding/conception, eating food a visitor left (+0.6), FLEE without damage (+0.4); failures (empty bush, unreachable target) are penalised.

**Update**: `w_a ← w_a + α (r − U_a) f`, `b_a ← b_a + α (r − U_a)`, α = 0.05, weights clamped to ±6. This is a per-creature contextual bandit with linear function approximation (no bootstrapped future value).

**Prior and inheritance**: each creature starts from a hand-written prior (coarse on purpose) plus individual noise and personality offsets. Offspring start from the mean of both parents' weights (blend 0.5) plus mutation noise, so learned tendencies are partly inherited.

**Survival reflexes (not learned)**: fleeing from strong fire, eating when hunger ≥ 80 and food is known, resting at energy < 8, foraging search when hungry with no known food. They bound the damage a bad learned policy can do.

## Wallet identity
Visitors act through authenticated wallet sessions. For every wallet a creature meets it keeps `wallets[addr] = {v ∈ [-1,1], n, last}` (max 32 per creature, weakest evicted). Events update `v` exponentially: a gift near the creature moves `v` toward +1 (rate 0.3), eating gifted food +1 (0.5), being hurt −1 (0.7), witnessing harm −1 (0.3). Utilities: `U(APPROACH) = b + 3v`, `U(AVOID) = b − 3v`, so later approach/avoidance changes. Wallets are **accounts, not people**; one person with many wallets looks like many strangers.

## Memory (separate from learning)
Each creature stores up to 40 episodic memories (tick, kind, text, valence, place; the least salient are forgotten first), remembered food places, relationships (affinity −1..1, max 24), and the last 12 decisions with utilities. Memory is recorded even when learning is disabled; only weight/opinion updates are switched off. Everything persists in snapshots.

## Speech
`server/src/speech.js` maps triggers (hungry, eat, tired, fire, storm, build_done, thanks, wary_visitor, bond, born, grief…) to fixed template lines and an emote. Triggers are raised by real events/needs, at most once per 40 ticks per creature. Bubbles carry `kind:"template"`, the template id and cause; the inspector says so. No text is generated by a model.

## Measured behaviour
`tests/results/learning-comparison.md` (generated by `tests/experiments/compare-learning.mjs`): 8 seeds × {learning on, off} from identical initial worlds. Clear measured effect: with learning on, creatures approach the helpful wallet and avoid the harmful one; with it off they do not discriminate. Weaker/non-significant effects on feeding and population are reported there with their spread.

## Limitations
* One-step bandit, no planning; reward shaping is hand-made and coarse.
* Priors, features and rewards were tuned by hand on a few seeds; results may not transfer to other configs.
* Opinions of wallets are per creature; there is no social transmission of opinions.
* Learned weights drift over very long runs; reflexes limit but do not remove bad policies (long run: starvation remains the main death cause once the population saturates the food supply — see `tests/RESULTS.md`).
* Creatures cannot tell an honest wallet from a Sybil swarm.

## Changing LEARNING for an existing world (Phase 1.1)
The setting is stored in the world snapshot. On every start:

| configuration | effect |
|---|---|
| `LEARNING` unset and no `world.learning` in `STRATOKS_CONFIG` | the world keeps its stored setting; the log says which |
| `LEARNING=0`/`false` or `world.learning:false` while the world has learning on | learning is **disabled from this start on**. Weights, memories, relationships and wallet opinions are kept exactly as they were; only further updates stop. A `learning_changed` event is emitted and the change appended to `world.learningLog`. |
| `LEARNING=1`/`true` or `world.learning:true` while learning is off | re-enabled the same way; updates resume from the preserved weights |
| any other `LEARNING` value (e.g. `off`) | startup fails: `LEARNING=off is invalid: use LEARNING=1 (enable) or LEARNING=0 (disable), or leave it unset…` |

`GET /api/status` → `learning` (boolean) and `learningPolicy {enabled, configured, source, action, policy, log}`.
Tested in `tests/repair.test.js` ("LEARNING: …"): enabled run → explicit disable (weights/memories byte-identical, 0 updates over 1,500 ticks) → unset (stays disabled) → explicit enable (updates resume).

## Phase 2A optional reduced circuit

The linear policy documented above remains the production default (`legacy`). Schema 3 adds an explicitly selected `mb-v1` circuit with sparse PN-like→KC-like expansion, competitive sparsity and reward-modulated opponent outputs. It is an independent reduced Drosophila-inspired model, not full brain emulation. Legacy weights are retained without claiming equivalent transfer. `mb-v1-frozen` freezes circuit plasticity and `mb-v1-ablated` removes learned outputs for causal controls. Operator activation is through `BRAIN_MODE` on restart; no client write endpoint is added.
